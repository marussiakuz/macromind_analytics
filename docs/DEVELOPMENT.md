# Разработка и локальная установка

Команды ниже рассчитаны на Linux/macOS. Начальная установка основных сервисов — в [README](../README.md).
Для Windows используйте соответствующие пути `.venv/Scripts/python`.

## Конфигурация

У каждого API свой `.env` в каталоге сервиса. Pydantic читает его из текущего каталога,
но не делает все значения переменными `os.environ` автоматически.

Основной API принимает только поля из `src/osint_agent/config.py`. Не добавляйте в его `.env`
произвольные параметры: неизвестные поля запрещены. Для режима без базы знаний
оставьте `KNOWLEDGE_DATABASE_URL` и токены пустыми. `DEMO_MODE=false` — реальные источники.

Дополнительные настройки, которые сейчас читаются непосредственно из окружения процесса:

| Переменная | Назначение |
|---|---|
| `MARKET_DB_PATH` | Путь SQLite рынка; по умолчанию `data/market.db` |
| `RADAR_LLM_API_KEY` | Отдельный ключ модели; без него используется ключ приложения |
| `QWEN_MODEL` | URI модели; по умолчанию `gpt://{folder}/qwen3.6-35b-a3b` |
| `YANDEX_LLM_URL` | Адрес совместимого API модели |

При необходимости передавайте их через окружение процесса. Они пока не объявлены в основном Settings.
Не переносите настройки другого приложения в этот `.env` целиком.
После правки `.env` полностью перезапускайте API и обработчик очереди.

## База знаний

Этот блок не нужен, чтобы запустить интерфейс или проверить реквизиты через Checko.
Для поиска по смыслу нужны все компоненты: PostgreSQL/pgvector, документы,
векторизация, обработчик очереди и разрешение доступа.

### PostgreSQL для разработки

Из `backend/osint-agent/`:

```bash
docker compose -f deploy/knowledge/docker-compose.knowledge-pg.yml up -d
# Дождитесь готовности контейнера, затем выполните миграции по порядку:
for migration in migrations/*.sql; do
  docker exec -i macromind-knowledge-pg psql -U knowledge -d knowledge -v ON_ERROR_STOP=1 < "$migration" || exit 1
done
```

Композиция по умолчанию публикует БД только на `127.0.0.1:5433`.
Пароль по умолчанию предназначен для локальной разработки. Не используйте его на сервере.
Если контейнер или порт уже существуют, сначала проверьте их владельца и содержимое.
Не применяйте миграции к чужой или рабочей БД в ходе эксперимента.
Миграции не имеют полноценного менеджера версий и отката; перед обновлением сохраняйте резервную копию.

В `.env` основного API настройте собственный DSN для БД, путь к документам и доступ:

```ini
KNOWLEDGE_DATABASE_URL=postgresql://knowledge:knowledge_local_dev@127.0.0.1:5433/knowledge
KNOWLEDGE_OBJECTS_ROOT=data/knowledge-objects
KNOWLEDGE_INTERNAL_TOKEN=REPLACE_WITH_SEPARATE_SERVICE_TOKEN
KNOWLEDGE_USER_ACCESS=analyst:REPLACE_WITH_USER_TOKEN:workspace-1
EMBEDDING_BASE_URL=http://127.0.0.1:8091
EMBEDDING_MODEL=Qwen/Qwen3-Embedding-0.6B
EMBEDDING_REVISION=main
EMBEDDING_DIMENSION=1024
KNOWLEDGE_SCHEMA_VERSION=0004
```

Значения `REPLACE_*` нужно заменить локально. В примере они не являются рабочими ключами.
Сервисный токен имеет широкий доступ. В браузер передавайте только отдельный пользовательский токен,
ограниченный рабочим пространством. Интерфейсный `VITE_KNOWLEDGE_API_KEY` виден в собранном коде.

### Векторизация текста

Отдельный Python-процесс переводит тексты в числовые векторы. Qwen для генерации через Yandex
этот сервис не заменяет. Модель загружается отдельно; нужны сеть, место на диске и оперативная память.
Точные ресурсы и готовность модели проверяйте на целевом сервере.

Из `backend/osint-agent/services/embedding/`:

```bash
python3 -m venv .venv
# Для CPU сначала установите подходящую сборку torch по инструкции вашей инфраструктуры.
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# Сервис читает именно переменные процесса; экспортируйте свой доверенный локальный образец.
set -a
. ./.env
set +a
.venv/bin/python -m uvicorn embedding_service:app --host 127.0.0.1 --port 8091
```

Его настройки называются `EMBED_MODEL_ID`, `EMBED_REVISION`, `EMBED_DIM`, `EMBED_MAX_TOKENS`,
`EMBED_MAX_BATCH`, `EMBED_QUEUE_LIMIT`. Это **не** имена параметров клиента основного API.

Проверка: `GET /health/live`, затем `GET /health/ready`. Только `ready=true` означает готовность модели.
`POST /internal/embeddings` получает `{"input_type":"query","texts":["текст"],"normalize":true}`.
Сервис пока не проверяет токен и не должен публиковаться в открытый интернет.
`EMBED_REVISION` сейчас обозначается в ответе, но `load_model()` не передаёт revision в загрузчик:
точную версию модели ещё нужно закрепить и проверить.

Список зависимостей сервиса перенесён из существующего сценария развёртывания.
Чистая установка и загрузка самой модели в этой проверке не выполнялись.

### Очередь индексации

Из `backend/osint-agent/`, с установленным окружением и своим `.env`:

```bash
.venv/bin/python -m osint_agent.knowledge.worker --interval 5
# Отдельный процесс контроля просроченных заданий:
.venv/bin/python -m osint_agent.knowledge.worker --reaper-only --interval 5
```

Без обработчика задания могут оставаться в очереди. `--once` выполняет одну итерацию.
Поиск по тексту может работать без векторов; поиск по смыслу требует завершённой индексации.
Пустой ответ базы означает отсутствие подходящих доказательств в разрешённом корпусе.
Он не доказывает отсутствие рынка или конкурентов.

### Наполнение корпуса

Рабочие материалы не включены в Git. Для проверочного импорта из файла используйте:

```bash
.venv/bin/python scripts/incognita_ingest_ab.py --dir /путь/к/документам --dry-run
```

Затем изучите `--help` и настройте параметры индексации/оценки. Не запускайте загрузку случайной
папки в рабочую базу. Для воспроизводимого запуска явно передавайте `--dir`, даже если архив находится в стандартной папке.
Шаблон вопросов: `data/incognita/questions_ab_template.json` в корне репозитория.
Пока это импорт файлов, а не гарантированная автоматическая загрузка архива Telegram.

### Размещение на серверах

- Сервер 1: основной API, PostgreSQL/pgvector, постоянные файлы документов, очередь и резервные копии.
- Сервер 2: векторизация на CPU в закрытой сети.
- Внешний провайдер: модель интерпретации через Yandex Studio.

Шаблоны находятся в `backend/osint-agent/deploy/knowledge/`.
Сценарии `deploy-server*.sh` содержат предположения о путях, сетях и привилегиях.
Перед использованием прочитайте их полностью и адаптируйте к инфраструктуре.
Не запускайте их как универсальную установку на любом сервере.
Реальные адреса, доступы и состояние серверов не подтверждаются содержимым репозитория.

## Порядок внесения изменений

1. Уточните сценарий пользователя и критерий готовности.
2. Найдите действующий путь в `docs/HANDOFF.md`; расширяйте существующую реализацию.
3. Для нового источника сохраните исходный ответ и отдельную нормализованную модель.
4. Проверьте корректный ответ, пустой ответ, неполные поля, ошибку доступа и тайм-аут.
5. Проверьте передачу данных от API до UI и экспорта. Ссылка должна подтверждать соседний вывод.
6. Запустите относящиеся к изменению тесты. Для новых зависимостей проверьте чистую установку.
7. Обновите документацию и зафиксируйте ограничения живой проверки.

Не добавляйте правила под конкретный ИНН, список заранее известных конкурентов или готовый отчёт
вместо общего алгоритма. Сайт компании подтверждает её заявления о продукции, но не её долю рынка.
Финансовая выручка компании не равна выручке отдельного продукта.
Сторона судебного дела или закупки не становится конкурентом автоматически.
Сохраняйте различия между фактом, прогнозом, заявлением компании и интерпретацией модели.
