# Основной API MacroMind Analytics

FastAPI-сервис компаний, реестров, финансов, исследований рынка и базы знаний.
Порт локальной разработки — **8000**.
Начните с [главного README](../../README.md) и [передачи разработки](../../docs/HANDOFF.md).

## Запуск из чистой копии

Нужен Python 3.10+. Команды выполняются из `backend/osint-agent`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
cp .env.example .env
.venv/bin/python -m uvicorn osint_agent.main:app --host 127.0.0.1 --port 8000
```

- Жив ли процесс: `GET /health`.
- Документация: http://localhost:8000/docs.
- `.env` читается из текущего каталога. Нельзя запускать из корня репозитория без подготовки окружения.
- Неизвестные поля в `.env` вызывают ошибку настроек. Используйте образец именно этого сервиса.
- После изменения `.env` нужен перезапуск.
- Старое `.venv` после переноса каталога не считается рабочим: создавайте окружение заново.

Базовый процесс запускается без Docker, Neo4j и Qdrant. Redis используется для кэша;
его недоступность не должна подменять ответ внешнего API демонстрационными данными.
`docker-compose.yml` — старый набор вспомогательной инфраструктуры. Он не запускает API
и не создаёт базу знаний с pgvector. Не запускайте всю композицию ради проверки ИНН.

## Основные маршруты

Все маршруты ниже имеют префикс `/api/v1`.

| Сценарий | Маршрут |
|---|---|
| Компания / ИП | `GET /counterparties/{inn}` |
| Поиск компаний | `GET /companies/search?q=...&by=name&obj=org` |
| Финансы | `GET /companies/{inn}/finances` |
| История событий | `GET /companies/{inn}/timeline` |
| Реестры | `GET /companies/{inn}/registry/...` — точные варианты в Swagger |
| Деловые связи физлица через Checko | `GET /persons/{inn}` |
| Граф | `GET /graph/{inn}` |
| Новое исследование | `POST /market/auto-analysis` |
| Восстановить сохранённое исследование | `GET /market/auto-analysis?legal_entity_inn=...` |
| Версии | `GET /market/auto-analysis/versions?legal_entity_inn=...` |
| База знаний | `/knowledge/*` — загрузка, поиск, доказательства, сигналы |

Checko: задайте `CHECKO_API_KEY`, оставьте `DEMO_MODE=false`.
10 цифр ИНН означают организацию, 12 — ИП. Контрольные цифры проверяются до запроса.
Проверка физлица — отдельный маршрут `/persons/{inn}`.
`null` в признаке риска означает отсутствие сведений, а не отрицательный результат проверки.

В UI Checko проходит через этот API. Отдельный `person-osint-agent` не заменяет этот путь.
Для новых контрактов расширяйте `connectors/checko.py`, модели, маршруты компаний, клиент UI и тесты.
Ошибки, пустые ответы и неполные данные должны различаться.

## Как формируется рыночный отчёт

1. Сведения Checko дают юридическую идентичность и возможный сайт.
2. `market/site_research.py` читает сайт и страницы продукции, выделяет направления и роли.
3. Прочитанные тексты передаются в определение продукта и контекст исследования.
4. Поисковые запросы формируются из продукта и применения. Используются Yandex Search и OpenAlex.
5. Найденные кандидаты требуют подтверждения продукции и сходства. Судебная или закупочная связь этого не доказывает.
6. Qwen через Yandex Studio интерпретирует материалы. Сервер связывает выводы с источниками и проверяет цитаты.
7. Итог сохраняется как версия в SQLite. UI и HTML-экспорт используют сохранённый результат.

Основная последовательность находится в `market/universal_analysis.py`.
Проверка и экспорт — в `market/analytical_report.py`.
Предварительная таблица `competitor_research` остаётся диагностикой и не должна заменять
проверенные описания в `analytical_report.competitors`.

Нужны `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `OPENALEX_API_KEY`.
Модель по умолчанию — Qwen3.6-35B-A3B через Yandex Studio.
Это действующая реализация, но универсальное качество поиска конкурентов ещё требует проверки
на независимом наборе компаний. Число «7–10 конкурентов» не гарантируется.

Отказ авторизации возвращает HTTP 503 с безопасной причиной. Новая успешная версия при этом
не создаётся. Повторное открытие сохранённого отчёта не вызывает модель.
Предыдущий отказ HTTP 401 не доказывает конкретный срок истечения ключа.

## Хранение и база знаний

- `data/market.db` — SQLite исследований рынка, создаётся автоматически.
- `data/audit/` — локальные журналы проверок, не публикуются в Git.
- `knowledge/pg_repository.py` — PostgreSQL/pgvector для базы знаний.
- `KNOWLEDGE_OBJECTS_ROOT` — файлы документов; это отдельное хранилище, не содержимое Git.
- `migrations/0001..0004` — SQL для PostgreSQL; выполняются по порядку.
- `knowledge/worker.py` — обработка очереди индексации и отдельный контроль просроченных задач.

Инструкция: [docs/DEVELOPMENT.md](../../docs/DEVELOPMENT.md#база-знаний).
Сервис векторизации разворачивается отдельно из `services/embedding/`.
Он не использует генеративную модель Qwen через Yandex.

## Тесты

```bash
.venv/bin/python -m pytest tests/unit tests/knowledge tests/integration/test_full_pipeline.py -q
```

Используйте тестовый `.env` без ключей и адресов рабочих БД.
Проверки PostgreSQL могут пропускаться, если тестовая БД недоступна.
Реальные сетевые проверки отделены в `tests/integration/test_real_api.py`.
Известные результаты и ограничения: [docs/VERIFICATION.md](../../docs/VERIFICATION.md).
